## 这个 Skill 做什么

把中文写得像一个克制、专业、说人话的同事，而不是 AI 生成的。适用于所有给人看的中文文字：文档、邮件、评论、汇报、说明。

## 何时使用

写或改任何中文内容时。判断标准很简单：这段字是给别人看的吗？是，就套这套规约。

不适用：代码注释里的技术术语、必须原样保留的引用文本。

## 标点（中英混排）

- 半角 `,` `.` `:` 后跟一个空格 —— `服务是 OS, 网关是引擎.`
- 半角引号 `" "` 和括号 `( )`，两侧留空格。
- 短并列项保留顿号 `、` —— `People、Community、Gallery`。
- ISO 日期，补零 —— `2026-07-14`。

## 用词（朴素）

- 避免：战略 / 未来 / 愿景 / 赋能 / 全面 / 打造 / 深度 / 系统性 / 行业领先。
- 换成：方向 / 目标 / 支持 / 升级 / 建 / 整合。
- 测试：一个词删掉不丢信息，就删掉。

## 忌 AI 腔句式

- 抽象收束句（"本质上都指向同一件事"）。
- 名词堆叠 + "性"（"系统性失灵"）。
- 三段以上排比。
- 反转修辞滥用（"这不是 X，是 Y"）。
- 工整的四元/三元框架。
- 表演式煽情开场白（"说句掏心的话 / 说句实在话 / 不瞒你说"）。要说直接说，或用"说到底 / 其实 / 别忘了"这类克制转折。

## 称呼

内部文档里用**同事 / 同学**，不用"读者"。

## 结构

- 强信号放最前，别把最好的东西埋进"专项补充"。
- 标题下一行放元数据：`作者, 2026-07-14, v1`。
- 引用保留英文原文 + 中文注解，不要只给译文。
- callout 用 `> [!note]` / `> [!warning]` / `> [!tip]`。

## 评论区回复（issue / MR / 讨论）

- 结论先行：抬头 `结论 + 一句话（≤50 字） + 要点（≤6 条）`，详情在后。
- 要点化：短句、列表；一条一动作；不复述上游与前文；通过类只留"评审通过，待合并"。
- 带证据：文件:行 / 端点 / MR / issue 链接。

## 一句话自检

写完回读一遍：

- [ ] 有没有虚大词？
- [ ] 有没有 AI 腔？
- [ ] 半角标点后的空格对不对？
- [ ] 是面向同事说话吗？

不过就改。
